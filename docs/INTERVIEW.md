# 实习展示与面试叙述

可用的项目名称：**DriveGaussianWorld：基于 DGGT 几何表征的行车世界模型工程**。

建议简历描述：

> 搭建面向道路行车的 Gaussian 世界模型原型，完成 KITTI 双目/OXTS 数据采集与审计、原生 DGGT 因果几何缓存、动作条件 GRU 多步预测、场景隔离评估、基线/消融和 CPU 推理 API；使用 22 项测试验证数据时序、坐标尺度、输入隔离与训练交付链路。

补充可以量化的工程事实：96 个真实行车采样时刻、192 张双目图像、318 个源文件校验，冻结 DGGT CPU 推理，新世界模型 319,551 参数，四组各 200 步 CPU 训练，26 个留出时间窗口。准确的数值结果见 `RESULTS.md`。不要把这些小样本窗口写成百万级数据或将当前实验写成高性能基准复现。

## 3 分钟讲解

1. **问题**：把静态重建表征扩成道路场景里的时间预测系统。DGGT 负责从历史图像提取几何；世界模型负责在给定运动条件下预测未来局部场景和观测，二者职责不同。
2. **关键工程决策**：每个时刻独立用历史前缀运行 DGGT。如果先用整段视频重建再切窗口，未来帧会通过注意力泄漏进训练输入。历史/未来条件/监督字段在代码接口中隔离。
3. **坐标与控制**：DGGT gauge 需要当时 stereo 尺度参考。当前动作是 OXTS 差分的运动代理，真实方向盘/油门控制和仿真干预需要额外数据。明确承认相机与 IMU 参考点近似。
4. **模型与实验**：图像与 Gaussian 集合编码成潜状态，动作 GRU 做开环多步预测，解析运动先验加学习残差。使用 val 选权重，test 保留，并比较 persistence、刚体运动、RGB-only、无动作和 stereo 表征。
5. **结果与下一步**：当前模型没有稳定打败简单图像基线，低分辨率几何也有明显误差。工程链路已跑通，下一步是更丰富的日志/原生分辨率/随机潜变量/独立几何与干预评估，而不是用“GPU 未跑”回避验证。

## 常见追问

**DGGT 为什么还不是世界模型？** DGGT 从观测图像重建相机和场景。未知未来动作下的时间递归与生成不是重建本身；这里新增状态转移、开环 rollout 与训练监督。

**未来动作从哪里来？** 条件预测实验从日志差分产生标签；推理 API 由调用方提出场景条件。无未来标签的评估采用当前速度下直行。不能把前者的指标称为未知未来运动预测。

**是不是把训练用的未来图像泄露给了模型？** target 只进入 loss。DGGT cache metadata 的 source frame 都不晚于其 observation；模型 observe 接口不接受 future 字段，测试修改 target 不改变预测。

**Gaussian 就是占据吗？** 不是。可见表面、alpha 和 confidence 不能自动解释为碰撞真值。当前候选动作排名只是接口演示，不报告安全成功率。

**几何误差是真实 3D 真值误差吗？** 默认 world-model 几何误差对比 DGGT 或 stereo 伪标签。独立 LiDAR 只做三个时刻的稀疏 patch 深度诊断，单独报告覆盖数，不能冒充标准 benchmark。

**RGB-only 消融真的移除了几何吗？** 是。观察编码中的 Gaussian 特征与后续几何 skip/warp 初始输入都被移除，单独测试任意改动输入 Gaussian 不改变该模型输出。

**能证明动作反事实可控吗？** 不能。模型对动作变化有响应有接口测试，但日志没有成对干预。需要仿真/真实 issued controls 与 intervention evaluation 才能验证动作因果效应。

**工程完成和研究成功有什么区别？** 本次已完成可复现数据—模型—训练—评估—API—报告链路，并报告失败的比较结果。高保真长时预测、泛化提升和真实闭环驾驶尚未达到，没有把这些能力写入交付清单。
